## 二、先统一工程，不要各建一套

沿用原约定：一个 Maven 工程，JDK 17、Spring Boot、MyBatis 接口/XML、MySQL、Thymeleaf、Bootstrap。具体依赖版本由刘梓烨选定并记录在 pom.xml 和 README，陈志鹏使用同一份工程。

## 四、数据库按当前 SQL，不照旧草案猜

表结构与约束以随包 `database/01_schema.sql` 为准；字段清单和用例看 `design/作业01内容基线.md`。不要按旧执行计划重新建表。

| 对象 | 本版本状态与主要流转 |
| --- | --- |
| 报名 enrollment | DRAFT → SUBMITTED → APPROVED / REJECTED；驳回后可修改重提；全额缴费后 ACTIVE；退费结算后 WITHDRAWN |
| 学员档案 student_profile | 业务约定使用 PENDING、ACTIVE、WITHDRAWN；报名生效、退学结算时同步更新 |
| 预约 training_booking | PENDING → ASSIGNED → COMPLETED；开始前可取消为 CANCELLED |
| 分配 training_assignment | ASSIGNED → COMPLETED / CANCELLED |
| 训练结果 training_record | COMPLETED / INVALID |
| 考试任务 mock_exam | DRAFT → SUBMITTED → PUBLISHED / REJECTED；驳回后修改再提交；PUBLISHED → CLOSED |
| 个人答卷 exam_attempt | IN_PROGRESS → SUBMITTED / EXPIRED |
| 退学申请 withdrawal_request | SUBMITTED → APPROVED / REJECTED；结算后 REFUNDED |
| 收款、退款记录 | SUCCESS / VOID |

旧草案中的预约 APPROVED、答卷 TIMED_OUT、退费 PAID 不能直接写入本版对应表。退学申请表叫 `withdrawal_request`，不是 `refund_request`。报名表当前也没有 REFUND_PENDING。

`user_id` 是账号 ID，`student_id` 和 `coach_id` 是档案 ID，不能混用。`mock_exam.question_count` 是抽题数 20，不是题包大小 100。作答使用 `exam_question_id`（题目快照 ID），不是题库的 `question_id`。

## 五、开始写页面之前，两人先确认接口

刘梓烨在共同工程中建立 `api_contract.md`，陈志鹏确认后再接页面。每个操作写清：地址、请求方式、参数、返回字段、允许角色、成功后的页面行为；同时确认 Mapper 方法名和参数。

共同格式沿用原约定：

- JSON 接口统一 `{code, message, data}`；错误使用相应 HTTP 状态：400 参数错误、401 未登录、403 无权限、404 不存在、409 状态或资源冲突。
- 业务 ID：Java 用 Long，对外 JSON 用十进制字符串。金额：Java 用 BigDecimal，对外用两位小数字符串。
- 时间对外用带 `+08:00` 偏移的 ISO 8601 格式；业务时区统一 Asia/Shanghai。
- 分页统一 `page` 从 1 开始、`pageSize` 默认 10；返回 `items、total、page、pageSize`。
- 页面路径、模板需要的 Model、接口路径要逐页写清。数据库菜单里已有的路径要能打开，不能只做一个样式菜单。
- 登录方案由刘梓烨统一实现。沿用 JWT 放 HttpOnly Cookie 的方案时，一并提供 CSRF Token 获取与提交方式，陈志鹏按约接入；不要双方各写一套登录。

页面只负责展示、收集输入和调用接口。审批、算分、权限、缴退款校验都放后端，不以隐藏按钮代替权限校验。公开注册只能注册学员。

## 六、必须跑通的业务规则

1. 报名审核通过后才能登记缴费。有效收款累计达到应缴金额时，同一事务内更新报名和学员档案。重复点击不能重复记款。
2. 只有有效学员能预约；开始前检查时段容量及学员、教练、车辆的时间冲突。预约不自动算学时，实际训练结果由教练登记。
3. 开考时一次性固定抽中的 20 题和顺序，刷新恢复原卷。交卷前的响应不能带正确答案或解析。后端判分；重复交卷返回原结果；截止时间由后端判断。
4. 发布后不修改该任务的快照及评分配置。关闭任务阻止新开答卷，不能把个人交卷当作关闭公共任务。
5. 退学有处理中申请时不再新增预约，提交申请时取消未来预约；已开始未完成的训练先处理。驳回后恢复新增资格，已取消预约不自动恢复。核定和实际退款都不能超过实缴余额，实际退款也不能超过核定额。
6. 退费结算在同一事务中写入退款记录、把申请改为 REFUNDED，并把对应报名及学员档案改为 WITHDRAWN；历史记录保留。当前无 REFUND_PENDING，处理中限制通过查询 SUBMITTED / APPROVED 申请实现。
7. 学员只查改自己的业务记录，教练只能登记自己负责的训练。每个写操作都检查当前角色、归属和状态，不能提供任意修改 status 的接口。
