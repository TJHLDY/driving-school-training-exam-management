## 三、关键业务规则落在哪里

业务规则没有只写在页面上，而是下沉到 SQL 和控制器，避免绕过页面直接调接口。

### 1. 用户管理

- 菜单不是写死的：`MenuMapper.selectByUserId` 用 `user_role` 连接 `menu` 查询，并按 `route_path` 去重。
  `academic` 同时是教务和教练，查出来是 4 条不重复菜单，而不是 6 条。
- 账号被业务记录引用时不允许删除，只能停用：`UserAccountMapper.countBusinessReference`。

### 2. 报名与入学

- 一位学员只有一份报名记录（`student_user_id` 唯一约束），驳回后改原记录重提，不新建第二条。
- 缴费一次全额：`EnrollmentMapper.registerPayment` 用**条件更新**把规则写进 SQL——
  只允许 `APPROVED` 状态、金额必须等于应缴金额；返回 0 就说明已经缴过费，从数据库层面防止重复收款。

### 3. 培训预约与学时

- 一条 `training_booking` 走完 `OPEN → PENDING → ASSIGNED → COMPLETED`，开始前可取消为 `CANCELLED`。
- 抢时段防并发：`claimOpenSlot` 是条件更新（`WHERE status='OPEN' AND student_user_id IS NULL`），
  影响行数为 0 说明被别人抢先，而不是先查再插。
- 冲突判断是**时间区间重叠**，不是开始时间相同：
  `新开始 < 已有结束 且 新结束 > 已有开始`，教练、车辆、学员三个维度都查。
- 分配车辆时校验车型与学员报名类型一致；登记学时时校验不超过实际训练时长。

### 4. 题库与模拟考试

- 题目直接归属考试任务（`question_bank.exam_id`），没有快照表。
- 开考时随机抽 20 题并写入 20 条 `exam_answer`，`position_no` 固定题序；刷新恢复原卷，不重抽。
- 答题查询 `selectForAnswering` **不返回** `correct_option` 和 `explanation`，解析只在交卷后的 `selectForReview` 返回。
- 交卷判分用条件更新（只允许 `IN_PROGRESS`），重复交卷返回 0，成绩不会被覆盖。

### 5. 退学与退费

- 处理中（`SUBMITTED` / `APPROVED`）不允许新增预约；提交申请时自动取消未来预约。
- 核定金额不能超过报名实缴金额（控制器校验）。
- 退款结算：`registerRefund` 只允许 `APPROVED` 且退款额等于核定额，返回 0 说明已结算过；
  同一事务里把报名改为 `WITHDRAWN`。

### 6. 登录与认证（JWT）

- 登录成功后签发 **JWT** 放进 **HttpOnly Cookie**，有效期 7 天，实现**七天免登录**。
- 令牌只放用户 ID 和登录名；拦截器用 Cookie 恢复登录时会**重新查一次角色**，管理员改过角色后立即生效。
- 签名校验挡得住篡改和伪造，令牌过期自动失效。
- 原理、代码位置、验证方法见 `docs/JWT登录与七天免登录说明.md`。

## 七、交接给刘梓烨（作业 03）的事项

### 需要搬进 Service 层的内容

目前控制器里直接调用映射器，以下 4 处已经加了 `@Transactional`，建议按业务搬进 Service 并保持事务边界：

1. `TrainingController.claim` —— 锁定时段行 + 认领 + 冲突检查
2. `TrainingController.cancel` —— 取消预约
3. `ExamController.start` / `submitAttempt` —— 创建答卷 + 写入 20 条明细 / 判分 + 交卷
4. `WithdrawalController.apply` / `refund` —— 提交申请并取消未来预约 / 退款并置报名 WITHDRAWN

### 需要补充的功能

- `api_contract.md`：按约定写明 URL、请求方式、参数、返回字段、允许角色、页面模板、Mapper 方法。
- JSON 统一返回 `{code, message, data}`，错误区分 400 / 401 / 403 / 404 / 409。
- 认证：已改为 **JWT 放 HttpOnly Cookie + 七天免登录**，实测通过。
  还需要补 CSRF 令牌；如果要求"退出即刻失效"，需要加令牌黑名单或改用短有效期 + 刷新令牌。
- Redis 菜单缓存：缓存角色或菜单变更后要失效。
- Postman 接口测试材料、并发测试（同一时段抢占、跨预约资源冲突）。

### 请不要改动的部分

- 页面路径要与 `menu.route_path` 保持一致，否则右侧菜单点不开。
- Mapper 方法名和参数是页面已经在用的，改名前先沟通。
- 数据库结构不要直接改，需要变更时先通知组长同步 SQL 与设计文档。
